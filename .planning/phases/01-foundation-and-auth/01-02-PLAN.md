# Phase 01 Plan 02: Login and Onboarding Flow Integration

## Objective

Wire the existing login and onboarding UI pages to the Better Auth backend. Replace the demo-only `router.push('/onboarding')` click handlers with real auth flows: phone OTP (send + verify), Apple Sign In, Google Sign In. Connect the onboarding page to persist user preferences (location, interests) via a tRPC mutation that updates the users table and marks onboarding complete.

## Context

Plan 01-01 established:
- Better Auth server config with Twilio Verify delegation (`src/server/auth.ts`)
- Client-side auth with `phoneNumberClient` plugin (`src/lib/auth-client.ts`)
- tRPC infrastructure with `publicProcedure` / `protectedProcedure` (`src/server/trpc/init.ts`)
- Auth router with demo login (`src/server/routers/auth.ts`)
- Drizzle schema: users table with interests, location, onboardingComplete (`src/server/db/schema/users.ts`)
- Login page with phone/Apple/Google buttons (`src/app/login/page.tsx`)
- Onboarding page with location picker and interest selector (`src/app/onboarding/page.tsx`)
- Proxy guard redirecting unauthenticated users on /onboarding, /profile (`src/app/proxy.ts`)
- Validators for phone number, OTP code, interests (`src/lib/validators/auth.ts`)

The login page buttons currently just do `router.push('/onboarding')` without any auth. This plan replaces those with real auth calls and persists onboarding data.

## Tasks

### Task 1: Wire login page to Better Auth flows
type="auto"

**What:**
- Replace the "Continue with Phone" button handler with a two-step OTP flow: phone input -> send OTP via `authClient.phoneNumber.sendVerificationOtp()`, then code input -> verify via `authClient.phoneNumber.verifyPhoneNumber()`. On success, redirect to `/onboarding` if `onboardingComplete` is false, otherwise to `/`.
- Replace the "Continue with Apple" button handler with `authClient.signIn.social({ provider: "apple" })`.
- Replace the "Continue with Google" button handler with `authClient.signIn.social({ provider: "google" })`.
- Add form state for phone number input and OTP code input.
- Add loading states and error display.
- Use the existing validators from `src/lib/validators/auth.ts` for client-side validation.

**Done when:**
- Login page shows phone input field, send OTP button, and after sending, shows code input field with verify button.
- Apple and Google buttons call the correct social sign-in methods.
- Successful auth redirects appropriately based on onboarding status.
- Error states are displayed to the user.
- All auth calls use the existing `authClient` from `src/lib/auth-client.ts`.

### Task 2: Wire onboarding page to persist preferences via tRPC
type="auto"

**What:**
- Create a `completeOnboarding` tRPC mutation in a new `src/server/routers/user.ts` router.
- The mutation accepts `{ location: string, interests: string[] }`, validates with zod, updates the authenticated user's `locationLabel`, `interests`, and sets `onboardingComplete = true` in the users table.
- Register the user router in `src/server/trpc/router.ts`.
- Update the onboarding page to call this mutation on "Get Started" click, then redirect to `/` on success.
- Add the `useSession` hook from `authClient` to the onboarding page to get the current user.
- Add loading/error states.

**Done when:**
- `completeOnboarding` mutation exists and is protected (requires auth session).
- Onboarding page calls the mutation with selected location and interests.
- On success, user is redirected to `/`.
- User record in DB has location, interests, and onboardingComplete updated.
- User router is registered in the app router.

### Task 3: Verify auth flow end-to-end
type="checkpoint:human-verify"

**What:** Verify the complete auth flow works visually and functionally.

**Verification steps:**
1. Visit `http://localhost:3000/login` - should see phone input, Apple, Google buttons.
2. Enter a phone number - OTP send button should be clickable with valid E.164 format.
3. Apple and Google buttons should initiate OAuth flows (will fail without real credentials, but should not crash).
4. Visit `/onboarding` while unauthenticated - should redirect to `/login`.
5. After onboarding completion, user should land on `/`.

## Success Criteria

- Login page has real auth integration (phone OTP + social providers)
- Onboarding page persists user data via tRPC mutation
- Protected routes redirect unauthenticated users
- No TypeScript errors in modified files
- All new code uses existing project patterns (authClient, tRPC, Drizzle)
